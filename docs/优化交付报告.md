## 二、变更摘要（按模块）

### 新增横切基础设施

| 文件 | 职责 |
|---|---|
| `core/config.js` | 超时 / 体积上限 / 并发度 / URL 长度上限收敛为单一事实源；`SITESEC_*` 环境变量覆盖；导出冻结对象 + `get(path)` |
| `core/errors.js` | `CODES` 错误码表（INVALID_URL / TIMEOUT / BODY_TOO_LARGE / DECOMPRESS_FAIL / PROBE_SKIPPED / …）、`appError` / `normalizeError` / `withTimeout` |
| `core/logger.js` | 单行 JSON 结构化日志写 **stderr**（不污染 NDJSON 进度流与 JSON 报告），默认 `warn`，`SITESEC_LOG_LEVEL` 可调，`redact()` 自动剥离 URL 查询串 |

> `withTimeout` 及各模块的兜底定时器**刻意不调用 `unref()`**：这些是防悬挂的最后保险，`unref` 会让纯 CPU / 单测场景在没有其它句柄时静默提前退出、测试跑到一半就断。本轮修过这个真 bug，见第七节。

### 采集层

- **`core/fetcher.js`** — `sniffCharset` + `TextDecoder` 多字符集解码（GBK / GB18030 / Big5 不再乱码）；解压后 4 MB 上限防压缩炸弹；协议校验、重定向循环与 `visited` 集合、非 `http(s)` 重定向拒绝、URL 内嵌凭据拒绝；截断立即结束响应。
- **`core/tls.js`** — 4 协议 × 5 弱套件探测由 11 次串行改为 `mapLimit` 并发（默认 4）；`socket.on('close')` 防悬挂；IPv6 方括号清理；输出 `durationMs`。
- **`core/dnschk.js`** — `withDeadline` 给系统 DNS 查询加超时，超时即回退 DoH（避免 c-ares 卡死）；`queryDnskey` 改查**可注册域**而非 host 子域（修漏报）；`tidyTxt` 去 BOM / trim 后再匹配 SPF / DMARC。
- **`core/content.js`** — 先剥离 HTML 注释再解析标签（防注释里的 `<script>` 误判）；单次标签扫描判脚本 / 表单 / 混合内容；`<a href>` 不再算混合内容（修误报）；凭据检测改「强特征 + 私钥头 + 内网 IP」与「弱特征需 ≥2 信号」；长注释切片分析不丢弃；`cms` / `frameworks` 拆分，`generator` 属性顺序无关且支持无引号值；ICP 正则覆盖「京ICP备…号」「ICP证」；修正 `isHtml` 判定。
- **`core/exposure.js`** — 9 阶段串行改并发；新增全量 `checked` 清单与 `failedRequests`；`probeBaseOf` 取**最终 URL 目录**（兼容子路径部署）；TRACE 需回显才判 enabled。
- **`core/libcheck.js`** — 组件特征只扫前 64 KB 且重置 `lastIndex` 防正则状态污染；超时 / 并发 / 上限统一取 config。
- **`core/util.js`** — `normalizeUrl` 拒绝控制字符、限制 URL 长度、拒绝内嵌凭据；`mapLimit` 增 `settle` 选项（单项异常转标准错误而不中断整批）。

### 编排与判定

- **`core/engine.js`** — 页面抓取后**五路并行**（重定向 / TLS / DNS / 组件库 / 暴露面）；`toHttpUrl` 处理 443→80 与自定义端口；`analyzeContent` 依 `isHtml` 决定是否告警；`performance` 分段计时；透传 `exposureDisabled` 与 `tech.frameworks`。
- **`core/standards.js`** — 新增 `prerequisite(ctx, id)` 前置条件守卫，包装全部 43 项检查：页面不可达 / 响应非 HTML / 暴露面未完成时，依赖该数据的项记 `na`（「无法检测」，**不计入评分分母**），从根上杜绝「没测 = 通过」。
- **`core/report.js`** — 6.2 增前端框架 / 响应类型 / 编码 / 扫描限制；暴露面增 `failedRequests`；新增 **6.5 检测范围与耗时**；局限条款补至 6 条（明确「无法检测≠通过」「DNSSEC 未验 DS 链与 RRSIG」）。
- **`core/index.js`** — 明确模块边界注释，新增导出 `CONFIG` / `logger` / `errors`。

### 服务层

- **`web/server.js`** — 接入 config / logger；并发队列增 `maxRequestQueueWait`（120 s）排队超时，返回 503；`acquire()` 包 try/catch；`health` 支持 HEAD；server error 结构化记录。
- **`desktop/main.js`** — `assess` IPC 包 try/catch，返回 `{ok:false,error}` 而非 reject（防渲染层未捕获异常）。

### 资源与文档

- **`tools/make-icon.js`** — 新 logo 生成逻辑（盾牌 + 放大镜），输出 `desktop/build/icon.png`、`icon.ico`、`logo.svg` 与 `ui/logo.svg`，四份共用同一套几何常量。
- **`ui/index.html` / `app.css` / `app.js`** — 见第五节。
- **`README.md`** — 同步新 logo 描述、测试清单、`SITESEC_*` 配置表、6.5 章节与前置守卫语义；修正重复标题与重复的「## 8」编号。
- **`docs/优化交付报告.md`** — 本文档。

## 三、准确性修正清单（误报 / 漏报）

| 编号 | 问题 | 性质 | 修复 |
|---|---|---|---|
| A1 | 纯 HTTP 站点被判「未配置 HSTS」`fail` | 误报 | T3 改 `na`（风险已由 T1 覆盖） |
| A2 | 页面正文含中文即判「缺 ICP 备案」`fail` | 误报 | P1 仅在 `cnDomain \|\| filingContext` 时才判 fail |
| A3 | 查到 DNSKEY 就直接 `pass`，声称 DNSSEC 已启用 | 过度承诺 / 误报 | N3 改 `info` 不计分；DNSKEY 改查可注册域（原查子域漏报） |
| A4 | 探测被关闭 / 请求失败 / 页面不可达时相关项仍按「通过」计分 | 系统性误报 | `prerequisite()` 统一守卫，记 `na` 并剔除出分母 |
| A5 | `<a href>` 外链被算作混合内容；注释里的 `<script>` 被算作内联脚本 | 误报 | 按属性遍历区分资源属性；先剥离注释再解析 |
| A6 | **以 `<!-- 注释 -->` 开头的页面被判非 HTML，整页内容分析被跳过** | **真 bug / 严重漏报** | `isHtml` 判定放宽为标签特征匹配；同步修复混合内容与超链接回归 |
| A7 | 凭据泄露仅凭弱特征单词即告警 | 误报 | 强特征直判，弱特征需 ≥2 信号（含私钥头 / 内网 IP） |
| A8 | 以 host 子域查 DNSKEY、TXT 带 BOM 未 trim | 漏报 | 改查可注册域；`tidyTxt` 归一化 |

此外补全了 **「无法检测」可见化**：暴露面输出 `checked` 全量清单与 `failedRequests`，报告 6.5 列出各阶段耗时与扫描限制（`scanLimited`），让用户能判断结论置信度，而不是把「没测到」当成「没问题」。

## 四、性能与资源

**编排变化**：抓取后五路并行 → TLS 协议/套件矩阵并发（4）→ 暴露面探测并发（6）→ 组件库抓取并发（3）；DNS 加超时避免 c-ares 卡死；各路径设响应体 / 解压体 / 扫描窗口上限，防止超大页面拖垮进程。

**本次提交前实测**（`git archive HEAD core` 导出旧版，同机、同目标、串行跑，输出为脚本单行 JSON）：

| 指标 | 旧版 HEAD | 优化后 | 变化 |
|---|---|---|---|
| example.com 总耗时 | 27526 ms | **8106 ms** | **3.4× 提速** |
| 其中五路并行探测 | — | 7019 ms | 新增分段计时 |
| 其中 TLS 探测 | — | 1944 ms | 新增分段计时 |
| 其中暴露面探测 | — | 4393 ms | 新增分段计时 |
| 检查项数量 | 43 | 43 | 不变 |

> 上一轮在同一目标测得 41578 ms → 8568 ms（约 4.9×）。公网目标受网络波动影响，倍率在 **3.4–4.9×** 区间；本地靶站端到端约 2.1 s、单次 TLS 探测约 32 ms、暴露面约 71 ms。资源侧新增解压 / 扫描上限，避免压缩炸弹与超大页面导致内存无界增长。

## 五、Logo 与 UI

### Logo 设计

**语义**：盾牌 = 安全防护 / 合规基线；放大镜 = 检测、审查、发现隐患。刻意不用「对勾 / 已通过」这类符号，因为工具定位是**发现问题**而非背书。旧版「轨道 / 电子」造型是 Electron 默认图标的改色，与安全评估无关，本轮替换为自有设计。

**规格**：浅粉圆角底 `#F9A8D4` + 深玫瑰盾 `#BE185D` + 近白放大镜 `#FFF7FB`，零渐变、纯几何扁平化，16 px 任务栏尺寸下仍可辨识。

**四份同源资源**（`tools/make-icon.js` 用同一套 `SHIELD` / `LENS` / `HANDLE` 几何常量生成）：

| 文件 | 用途 |
|---|---|
| `ui/logo.svg` | 页面 favicon / 共享前端矢量源 |
| `desktop/build/logo.svg` | 桌面版矢量源（与 UI 一致） |
| `desktop/build/icon.png` | 512×512 窗口 / 任务栏图标 |
| `desktop/build/icon.ico` | 16/32/48/64/128/256 多尺寸 exe 图标 |

页面顶栏另用内联 SVG（无外部请求、随主题走）。便携版与安装版 exe 均已重打包带新图标。

### UI 改动

- **信息层级 / 可读性**：基准字号 14.5 px；次级文字由浅灰改为 `#835c74` 提升对比度；标题 / 证据 / 说明分层；证据卡新增前端框架、响应类型、页面编码、`scanLimited`、探测失败清单；明细加性能耗时行。
- **视觉一致性**：清除旧轨道造型残留与注入的 `data-page-node-id` 噪音；logo 类名统一为 `.lm-shield` / `.lm-lens` / `.lm-handle`。
- **交互清晰度**：`type="url"` 输入、`<noscript>` 提示；`?url=` 仅预填，必须显式 `&auto=1` 才自动评估（防恶意链接在本机触发 SSRF）。
- **无障碍**：`skip-link` 跳至主内容、ARIA 标注、`:focus-visible` 焦点描边、`prefers-contrast: more`、动效尊重 `prefers-reduced-motion`。
- **响应式**：1024 / 720 / 480 三档断点；给 flex 子项加 `min-width:0` 并设 `html,body{overflow-x:clip}`，修复窄屏顶栏长中文副标题横向撑破容器；品牌副标题收起断点由 480 提前到 720。
- **验证截图**：`test/shots/21-optimized-wide.png`（宽屏结果态）、`23-optimized-narrow-fixed.png`（窄屏修复后）、`24-optimized-initial.png`（初始态）。

## 七、Review / 构建 / 测试中发现并修复的问题

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | **测试进程 exit=0 但日志中途截断、部分断言未执行** | 所有兜底定时器调用 `unref()`，纯 CPU / 单测时无其它事件循环句柄 → 进程静默退出，超时兜底永不触发 | 移除 `errors.js` / `fetcher.js` / `tls.js` / `dnschk.js` 中兜底定时器的 `unref()`（`web/server.js` 的空闲退出定时器因有 HTTP 监听句柄保活，属合理用法，保留） |
| 2 | **注释开头的页面被判非 HTML，整页内容分析跳过** | `looksHtml` 要求头部出现特定标签 | 改为标签特征匹配；连带修复混合内容 / 超链接回归 |
| 3 | **窄屏顶栏副标题横向溢出** | flex 子项默认 `min-width:auto`，长中文撑破容器 | `min-width:0` + `overflow-x:clip` + 断点提前 |
| 4 | 强凭据注释断言拿到 `undefined` | 同 #2 的连带影响 | 同 #2 |
| 5 | 解压体截断测试断言失败 | 测试体仅 2 MB，小于 4 MB 上限 | 加大测试体，断言改为 `< CONFIG.limits.maxDecompressed` |
| 6 | E2 文案断言不匹配 | 测试硬编码「不适用」，实际为「无法判定」 | 断言改为「无法判定」并补「按设置关闭」分支 |
| 7 | 分数在无头虚拟时间下显示 `0.0` | 虚拟时间不推进 `requestAnimationFrame`，是验证环境假象 | 用 `prefers-reduced-motion` 复验显示 69.2，确认非产品 bug |

## 九、遗留边界与建议

- DNSSEC 仍只检查区顶点 DNSKEY 是否存在，**未验证 DS 信任链与 RRSIG**；因此保持 `info` 不计分。若需权威结论应接外部验证服务。
- 报告结论是「外部可见面 + 被动 / 低强度探测」视角，WAF / CDN 会改变响应头与错误页表现，不等同于渗透测试或等保测评结论。
- 超大页面按 1 MB 压缩 / 4 MB 解压 / 256 KB 正文 / 64 KB 组件特征截断并标记 `scanLimited`，极端情况可能漏检，报告 6.2 / 6.5 已注明。
- 便携版 / 安装版 exe 为**未签名**构建，分发时 Windows SmartScreen 会提示「未知发布者」，属正常现象。
- 内层 exe 因关闭资源重写仍保留 Electron 默认文件图标，但运行时窗口 / 任务栏与外网封装 exe 图标均为本项目新 logo。
